심화 5

반도체 특화 — SAP 구현과 전자구매 연계

4-3이 "반도체 구매가 어떻게 생겼나"였다면, 여기서는 그걸 SAP의 어떤 모듈·기능으로 구현하고, 어떤 인터페이스를 깔아야 하는지까지 내려간다.

1. 장비 CAPEX — IM·PS·AA가 함께 움직인다

장비 한 대의 구매는 MM 혼자 처리하지 못한다. 투자관리(IM) → 프로젝트(PS) → 구매(MM) → 자산회계(AA)가 릴레이로 이어진다.

전자구매 연계 포인트 수리 포털에는 시리얼 번호 단위의 수리 이력(견적 → 승인 → 수리 → 시험성적)이 쌓여야 한다. "이 펌프 3번째 수리인데 신품보다 비싸졌다" 같은 수리 vs 교체 판단이 데이터로 가능해진다.

  • 거래 상대 제재 리스트 스크리닝(SPL): 협력사 등록 시점(포털)과 거래 시점(SAP) 이중 체크

5. 반도체 Fab의 인터페이스 목록 — 일반 제조와의 차이

3-2차시의 표준 목록(마스터+트랜잭션) 위에 반도체 특화분이 얹힌다.

인터페이스방향내용기술 힌트
마일스톤 상태장비 포털 → SAPFAT/SAT 승인 → Invoicing Plan 회차 해제이벤트 API + 문서 첨부
재고 텔레메트리SAP/IoT → 공급사탱크 레벨·위탁 재고 수준 (시간 단위)센서 → IoT 플랫폼 → API
VMI 보충 통보공급사 → SAP보충 수량·도착 예정 → 입고 예정DESADV 또는 API
사용량 정산MES/유량계 → SAP월 사용량 집계 → ERS 정산 근거MES 연계 — 검침 확정 절차 필요
정산 명세 회신SAP → 포털ERS 결과 명세 → 공급사 확인·이의월 배치 + 이의 워크플로우
수리 이력포털 ↔ SAP시리얼 단위 견적·수리·시험성적시리얼 키 필수
제재 스크리닝포털 → GTS협력사 등록 시 SPL 체크등록 승인 전 동기 호출

6. 운영 체크리스트 — 반도체판

항목왜 반도체에서 특히 중요한가
ERS 단가 유효성 모니터링Info Record 단가 만료 = 정산 전체 중단. 만료 30일 전 알림 배치
검침(사용량) 확정 절차유량계 보정·결측 보간 규칙을 공급사와 합의 — 분쟁의 단골
긴급 구매 트랙 별도화라인 정지 시 평시 승인 절차로는 못 버틴다. 사후 결재 + 전용 문서유형으로 통계 분리
ECCN 분류 현행화규제 목록 개정 시 자재 마스터 일괄 재분류 — 연 단위 정비 일정 필요
위탁 재고 실사공급사 소유지만 우리 Fab 안 — 실사 책임·차이 정산 룰을 계약에 명시
심화 5의 핵심 한 줄 반도체 구매 시스템은 MM 하나가 아니라 IM·PS·AA(장비) + MM·QM(자재) + PM(스페어) + GTS(규제)의 합주다. 전자구매 연계도 "PO 주고받기"가 아니라 마일스톤·텔레메트리·사용량·시리얼 같은 비정형 데이터의 왕복이 본체가 된다.
