심화 2

Ariba · CIG 매핑 실무

2차시에서 "표준 통로"라고 했던 CIG의 안쪽 — cXML 문서 구조, IDoc과의 매핑, 프로젝트 진행 순서.

1. cXML — Ariba 세계의 공용어

Ariba Network를 오가는 모든 문서는 cXML(commerce XML)이다. IDoc이 세그먼트 계층이라면 cXML은 XML 엘리먼트 계층 — 구조 철학은 놀랄 만큼 비슷하다.

cXML 문서내용IDoc 대응 (3차시)
OrderRequestPO 송신ORDERS
ConfirmationRequest주문 확인ORDRSP
ShipNoticeRequest납품 통보(ASN)DESADV
InvoiceDetailRequest송장INVOIC
PunchOutSetupRequestPunch-out 세션 시작(OCI 로그인 호출)

  style G2 fill:#e8f0fe,stroke:#1a73e8,color:#1a73e8
  • 표준 매핑 제공: ORDERS05 ↔ OrderRequest 같은 흔한 변환은 SAP이 미리 만들어 둠 — 프로젝트는 "차이"만 메운다
  • 커스텀 매핑: Z-필드, 한국 특화 항목(사업자번호, 세금계산서 정보)은 CIG 매핑 편집기에서 XSLT성 규칙으로 추가
  • 모니터링: 문서별 전송 상태 추적 화면 제공 — 3-2차시의 "상태 가시성"을 일부 대신해 준다

3. 매핑 정의서에서 실제로 싸우는 지점들

이슈내용해법의 방향
코드 체계 불일치SAP 단위(EA/ST) ↔ cXML 표준 단위(UN/PCE), 통화·국가 코드 차이변환 테이블을 CIG 한 곳에서 관리 (양쪽 시스템에 흩뿌리지 말 것)
세금 표현한국 부가세 10%를 cXML Tax 구조로 — 세금계산서 모델(5차시)과 정합 필요세금은 헤더/품목 어느 레벨로 보낼지 초기에 합의
첨부 파일도면·시방서를 PO에 첨부cXML Attachment(MIME) 지원 범위·용량 제한 확인
Z-필드현장코드·프로젝트번호 같은 커스텀 항목cXML Extrinsic 엘리먼트로 — 남발하면 유지보수 부채
변경/취소PO 변경 시 전체 재전송인가 변경분인가Ariba는 전체 재전송(orderID + 버전) — SAP ORDCHG 발상과 달라 혼동 주의
