조직 구조 & 마스터 데이터

외부 전자구매 시스템이 SAP에 보내는 모든 데이터는 결국 이 구조 어딘가에 꽂힌다. 연계 설계의 출발점.

1. 조직 구조 (Enterprise Structure)

SAP에서 구매가 일어나는 "장소"의 계층 구조다. 재무(법인), 물류(공장), 구매(구매조직)의 세 축이 서로 할당 관계로 엮인다.

Client (전사)하나의 SAP 시스템 전체. 그룹 전체를 담는 최상위 단위
Company Code (회사 코드)법인 단위 — 재무제표가 나오는 단위. 송장·지급의 주체
Plant (플랜트)공장/사업장 — 재고가 잡히고 MRP가 돌아가는 단위. 입고의 주체
Storage Location (저장 위치)플랜트 내 창고/구역 단위
Purchasing Organization (구매 조직)구매 계약·단가의 법적 주체. Company Code 또는 Plant에 할당
Purchasing Group (구매 그룹)실제 구매 담당자/팀. 문서의 담당자 필드
왜 구매조직만 점선(별도 축)인가? 구매조직은 법인 계층에 종속되지 않는다. 하나의 중앙 구매조직이 여러 법인을 커버하는 그룹 통합구매 구조가 가능하기 때문. 단가 협상은 그룹이 하고, 발주·지급은 각 법인이 하는 형태다.
연계 설계 단골 이슈 전자구매 포털의 "구매 부서/사업장" 개념을 SAP의 Purchasing Org / Purchasing Group / Plant에 어떻게 매핑할지가 프로젝트 초기의 핵심 설계 결정이다. 매핑이 어긋나면 포털에서 넘어온 PO의 권한·승인선·회계 귀속이 전부 꼬인다.

2. 마스터 데이터 5대장

자재 마스터 × 공급업체 (BP) = Info Record

MM01/03		 품목 정보. 구매·MRP·회계 등 부서별 뷰(View) 구조 포털 카탈로그 품목 ↔ SAP 자재코드 매핑이 최대 난제. 코드 없는 품목(텍스트 PO) 처리 정책 필요

3. 마스터 동기화의 기본 방향

1협력사 등록 포털 → SAP 공급사가 포털에 가입·심사 통과 → SAP에 Business Partner 생성 (인터페이스 또는 수동 승인 후 생성)
↓
2품목/카탈로그 SAP → 포털 SAP 자재 마스터를 포털 카탈로그의 기준으로 배포. 비코드 품목은 포털에서만 관리하고 텍스트로 PO 생성
↓
3단가/계약 포털 → SAP 입찰·협상 결과(낙찰 단가)를 Info Record / 계약으로 전송. 이후 SAP PO가 이 단가를 자동 참조
기억할 것 마스터의 원본(Master of Record)이 어디인지부터 정하라. 업체 마스터는 보통 포털이 원본, 자재 마스터는 SAP이 원본, 단가는 "포털에서 결정 → SAP에 반영"이 일반적이다.
