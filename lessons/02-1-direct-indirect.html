2-1

직접구매 vs 간접구매

전자구매 시스템의 아키텍처가 갈라지는 근본 이유. "무엇을 사느냐"가 아니라 "구매가 어떻게 시작되느냐"의 차이다.

1. 정의부터

직접구매 (Direct)

  • 생산에 투입되는 원자재·부품·외주가공품
  • 수요의 출발점: MRP (생산계획이 자동 계산)
  • 자재 마스터·BOM·단가계약이 필수 전제
  • 반복 발주 — 같은 품목을 같은 업체에서 계속
  • 매출원가에 직결 → 단가 1원에 민감

간접구매 (Indirect / MRO)

  • 생산에 직접 안 들어가는 소모품·설비·용역·IT·마케팅
  • 수요의 출발점: 현업 사용자의 요청
  • 자재코드가 없는 품목이 대부분 (텍스트/카탈로그)
  • 비반복·다품종 소액 — 누가 뭘 살지 예측 불가
  • 비용 통제(예산·승인)가 핵심 관심사

2. 흐름이 어떻게 다른가

직접구매 — 시스템이 시스템에게 (사람 개입 최소화)

1생산계획 → MRP 실행 완제품 계획을 BOM으로 전개해 "언제 무엇이 몇 개 부족한지" 자동 계산
↓
2PR 자동 생성 → 공급원 자동 결정 소스리스트·단가계약이 있으면 사람 손 없이 PO까지 자동 전환 가능
↓
3PO 송신 → 공급사 협업 주문확인(ORDRSP)·납품통보(ASN)·사급재 수불 — 협력사 포털/EDI가 개입하는 구간
직접구매 전자화의 초점 "쇼핑 경험"이 아니라 공급사와의 데이터 협업(SCC: Supply Chain Collaboration)이다. 입찰은 신규 소싱·연간 단가계약 때만 발생한다.

간접구매 — 사람이 쇼핑하듯 (사용자 경험이 핵심)

1현업 사용자가 요청 카탈로그 검색 또는 Punch-out(외부 쇼핑몰 연동)으로 장바구니 구성 — 전자구매 포털이 개입하는 구간
↓
2승인 워크플로우 금액·품목·예산에 따른 다단계 승인. 코스트센터/WBS 계정 지정 필수
↓
3PO 생성 → 납품 → 검수 확인 요청자가 직접 "받았다" 확인(Confirmation)하는 경우가 많음. 서비스면 SES 검수
간접구매 전자화의 초점 누구나 교육 없이 쓸 수 있는 쇼핑몰 수준의 UX + 새는 돈을 막는 승인·예산 통제. Ariba Buying, Coupa가 이 영역에서 출발한 제품이다.

4. 그래서 아키텍처가 갈라진다

직접구매 연계 = SAP이 중심

  • PR/PO 생성의 주체가 SAP(MRP)
  • 포털은 SAP 문서를 공급사에 보여주고 회신받는 창구
  • 흐름: SAP → 협력사 포털 → 공급사 → SAP

간접구매 연계 = 포털이 중심

  • 요청·승인·카탈로그가 전부 포털에서 발생
  • SAP은 PO·회계 처리를 받는 백엔드 원장
  • 흐름: 사용자 → 포털 → SAP → (지급)
실무에서 가장 흔한 오해 "전자구매 시스템 하나로 직접·간접을 다 커버한다"는 계획은 대부분 실패한다. 두 영역은 사용자도, 데이터 전제도, 통제 포인트도 다르기 때문에, 같은 플랫폼을 쓰더라도 프로세스 설계는 분리해야 한다.
