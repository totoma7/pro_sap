심화 3

종합 케이스 스터디 — 가상 그룹사 구매포털 구축

1~5차시 전부를 한 시나리오에 적용한다. 가상의 "한울그룹" 구매포털 구축을 처음부터 설계해 보자.

0. 상황 설정

한울그룹 — 3개 계열사, 단일 SAP ECC(S/4 전환 예정)
  • 한울전자 (제조): 부품 직접구매 + 외주 사급. 협력사 800개
  • 한울건설 (건설): 하도급 외주 중심. 협력사 1,200개
  • 한울서비스 (금융/서비스): 100% 간접구매

목표: 그룹 통합 구매포털 신축. 입찰·협력사 관리·전자계약은 포털, 원장은 SAP.

1단계. 조직 설계 — 1차시 적용

결정

  • 그룹 중앙 구매조직 1000 신설 — 공통 품목 통합 단가계약
  • 계열사별 구매조직(1100/1200/1300)은 유지 — 회사별 발주·지급
  • 포털 유입 PO에 전용 문서유형 ZNB 부여

근거 (배운 것)

  • 구매조직은 법인과 별도 축 — 통합구매 가능 (1-1)
  • 전용 Document Type = 추적·권한·통계 분리 (1-3)
  • 업종이 다르면 Item Category 주력이 다름 — 전자 L, 건설 D, 서비스 D (1-3, 4차시)

2단계. 마스터 원본 정의 — 1-1·3-2 적용

데이터원본동기화
협력사포털 (등록·심사·평가)승인 시 실시간 → SAP BP 생성. 제재(거래정지)도 즉시 반영
자재SAP일배치 + 변경분 → 포털 카탈로그
단가/계약포털에서 결정 → SAP이 원장낙찰 확정 시 실시간 → Info Record/계약
코스트센터·WBSSAP일배치 → 포털 (간접구매 계정지정·건설 기성 귀속용)

3단계. 인터페이스 목록 — 3차시 적용 (계열사별로 다르다!)

공통 (3사 전체) 마스터 4종(위 표) + 포털 PR→SAP(BAPI_PR_CREATE) + SAP PO→포털(ORDERS05) + 입고결과 회신 + 송장(INVOIC) + 지급상태 회신
↓ 업종별 추가
한울전자 (제조) + 납품 스케줄 송신(SA 회차) + ASN 수신(DESADV→Inbound Delivery) + 사급재 수불 공유 + QM 판정 회신 (4-1)
↓
한울건설 + 기성 신청 수신→SES 생성(ML81N 대응 BAPI) + 유보금·선급금 정산 데이터 + 하도급 서면 발급 이력 (4-2)
↓
한울서비스 (간접) + 카탈로그/Punch-out(OCI) + 예산 가용액 실시간 조회(동기 RFC) — 품의 시점 차단용 (2-1, 4-2)
↓ 한국 공통
세금계산서 (5차시) 역발행: 입고/SES 실적 → 포털에서 세금계산서 작성 → 공급사 승인 → ASP 국세청 전송 → 승인번호 포함 송장을 SAP IV로
여기서 보이는 것 "그룹 공통 포털"이라도 인터페이스의 절반은 업종별 전용이다. 공통 레이어와 업종 레이어를 처음부터 분리 설계해야 한 계열사 요건 변경이 전체를 흔들지 않는다.

4단계. 장애 시나리오 리허설 — 3-2·심화 1 적용

시나리오증상대응 설계
송장 인터페이스 3일 중단GR/IR 잔액 급증, 지급 지연 민원일일 대사가 1일 차에 탐지 → 재처리 큐 + 협력사 공지 자동화
PO 생성 타임아웃 재시도동일 PO 중복 생성 위험포털 문서번호 멱등 키 — 중복이면 기존 PO번호 회신
협력사 제재 반영 누락거래정지 업체에 발주 발생제재는 동기 인터페이스 + SAP 측 구매 차단 플래그 이중화
월말 결산 중 송장 유입재무 숫자 변동마감 캘린더 — 결산 D-1 컷오프, 이후 건은 익월 큐

5단계. 남는 질문 — S/4 전환 대비

  • Vendor → Business Partner 전환: 포털-BP 동기화 인터페이스 재작업 (1-1)
  • 인터페이스 신규분은 OData 우선으로 — IDoc 신규 개발 최소화 (3-1)
  • 서비스 구매가 S/4에서 Lean Service 모델로 변경 — 건설 SES 연계 영향 분석 필요
케이스 스터디의 교훈 설계 결정 하나하나가 앞 차시의 개념과 1:1로 연결된다. 새 프로젝트를 만나면 이 순서로 점검하라 — ① 조직·문서유형 ② 마스터 원본 ③ 공통/업종별 인터페이스 ④ 장애 리허설 ⑤ 미래(S/4) 대비.
